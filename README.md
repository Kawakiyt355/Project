# ModelControl

Интерактивный 3D-симулятор мониторинга и управления автономными роботами на виртуальном складе.
Учебный / демонстрационный проект: работает полностью локально, без интернета, сервера и базы данных,
не подключается к реальным устройствам.

> **Важно: статус проверки.** Проект написан в среде, где Godot не был установлен, поэтому
> **приложение ни разу не запускалось**. Код проверен только статически и отдельными расчётами на Python
> (см. раздел «Какие проверки реально выполнены»). При первом запуске возможны ошибки разбора или
> выполнения GDScript — их текст появится в панели *Output* / *Debugger* редактора Godot.

## Реализованные функции

- 3D-склад 24×16 ячеек: пол с видимой сеткой навигации, стены, 5 блоков стеллажей, 4 ящика-препятствия, 5 точек назначения (A–E), зарядная станция, освещение с тенями.
- 5 роботов (R-01…R-05) из простых примитивов: у каждого свой цвет корпуса, метка с ID над ним и лампа-индикатор состояния.
- Состояния робота: **Idle, Moving, Working, Paused, Disabled** с контролируемыми переходами (по прибытии: Working ~2 с → Idle).
- Маршрутизация: A* по 4 направлениям с манхэттенской эвристикой; учитываются границы, стеллажи и позиции других роботов.
- Плавное движение между центрами ячеек (без телепортации), поворот робота по направлению движения.
- Защита от столкновений: резервирование ячеек; два робота не занимают одну ячейку и не меняются местами сквозь друг друга; при блокировке робот ждёт, через 1,5 с пересчитывает маршрут в обход, через 6 с пишет предупреждение в журнал, через 20 с отменяет задание.
- Команды для выбранного робота: **Move, Pause, Resume, Reset, Disable/Enable, Remove** (удаление — с подтверждением). Отключённый робот остаётся в сцене, но не движется; удалённый исчезает.
- Невалидные цели (за картой, стеллаж/ящик, занятая ячейка, цель уже назначена другому роботу, нет маршрута) отклоняются с понятным сообщением.
- Маршрут выбранного робота отображается точками по центрам ячеек и кольцом на цели; выбранный робот подсвечен кольцом в сцене и в списке.
- Общие команды: **Start/Pause**, **Resume** (возобновить всех на паузе), **Reset Simulation**, **Add Robot** (до 10), **Demo Tasks**, скорость симуляции ×0,25…×4, **Reset Camera**.
- Журнал событий с отметками времени (также дублируется в консоль Godot).

## Технологии

Godot 4 (рендерер Compatibility), GDScript, процедурные примитивы (`BoxMesh`, `CylinderMesh`, `SphereMesh`, `TorusMesh`, `ImmediateMesh`, `MultiMesh`), встроенные Control-узлы. Сторонних зависимостей и ассетов нет.

## Требования

- macOS, **Godot 4.2 или новее** (стандартная сборка, не .NET) — https://godotengine.org/download
- Видеокарта с поддержкой OpenGL 3.3 (используется рендерер Compatibility).

## Как открыть и запустить на macOS

1. Скачайте Godot 4, распакуйте `Godot.app` (например, в «Программы»). При первом запуске macOS может потребовать подтвердить открытие в «Системные настройки → Конфиденциальность и безопасность».
2. В менеджере проектов нажмите **Import** (Импорт) и выберите файл `project.godot` из папки `ModelControl`.
3. Откройте проект. При первом открытии Godot построит кэш `.godot/` и зарегистрирует классы `class_name` — подождите окончания импорта.
4. Нажмите **F5** (▶ Run Project). Главная сцена `res://scenes/main.tscn` уже указана в настройках проекта.

## Управление

**Камера (в области 3D):**

| Действие | Как |
|---|---|
| Вращение | правая кнопка мыши + движение или Option + левая кнопка |
| Сдвиг | средняя кнопка, Shift + ПКМ или Shift + ЛКМ |
| Масштаб | колесо мыши, жесты трекпада (щипок / прокрутка двумя пальцами) |
| Движение камеры | WASD или стрелки |
| Поворот | Q / E |
| Сброс | кнопка *Reset Camera* |

**Роботы:**

1. Кликните по роботу в сцене или в списке слева — он будет выделен, справа появится его состояние.
2. **Move** → кликните по ячейке склада (зелёная подсветка — цель допустима, красная — нет). **Esc** отменяет режим.
3. **Pause / Resume / Reset / Disable (Enable) / Remove** — кнопки справа; недоступные в текущем состоянии кнопки затемнены.
4. Общие команды — в нижней панели; **Пробел** — пауза/запуск симуляции.

## Известные ограничения

- Приложение не запускалось в Godot (см. выше); возможны ошибки, которые нужно будет исправить по сообщениям редактора.
- Планирование — не промышленное: без согласованного планирования флота. Взаимная блокировка в узком месте разрешается пересчётом маршрута и, в худшем случае, отменой задания через 20 с. На широком складе это работает, но на тесных картах возможны остановки.
- Pause/Disable посреди шага замораживают робота между двумя ячейками; он продолжает удерживать обе ячейки.
- Если при Reset стартовая ячейка занята другим роботом, робот возвращается в ближайшую свободную (запись в журнале).
- 3D-вид рендерится во вложенном `SubViewport` и при масштабировании окна (режим `canvas_items`) может выглядеть слегка мягче, чем интерфейс.
- Состояние симуляции не сохраняется между запусками; карта задана в `warehouse_grid.gd` и не редактируется из интерфейса.
- Экспорт в `.app` не настраивался.

## Какие проверки реально выполнены

Выполнено (в среде без Godot):

- Проверено, что `run/main_scene` и все пути `res://` в `project.godot` и `main.tscn` указывают на существующие файлы.
- Скрипт-проверка исходников: отступы только табами, баланс скобок, все `class_name` определены, методы, вызываемые из других скриптов (`manager.*`, `ui.*`, `grid.*`, `rig.*`), существуют.
- Данные карты прочитаны из `warehouse_grid.gd` и проверены на Python: стартовые ячейки, точки назначения и зарядная станция проходимы, стартовые ячейки уникальны.
- **Порт** алгоритма A* на Python (не сам GDScript) на этих данных: для 30 пар «старт → точка назначения» путь допустим и такой же длины, как у поиска в ширину; на 300 случайных парах длина совпала; цели на стеллаже и за границей отклоняются.

**Не выполнено:** запуск проекта, разбор GDScript движком Godot, проверка интерфейса, выбор мышью, движение, пауза/возобновление, сброс, отключение, удаление, добавление робота, обработка конфликтов в реальной сцене. Эти пункты нужно проверить вручную при первом запуске.
